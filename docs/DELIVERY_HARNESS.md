# 안내서 생성 및 배포 계약

2026-10-26 오류를 실제 생성 경로에서 차단하고, 2026-11-11 승인된 후보 선별 기준을 적용함. 기존 산출물·미커밋 변경은 보존하고 이후 실행에 적용함.

## 기본 산출물

기간 요청은 docs/CANDIDATE_SELECTION.md에 따라 우선 안내로 선정된 개정 버전별 개별 안내서 + 목차 + 요약문을 기본 생성함. 전체 탐지 후보는 원문·분류·미발행 사유를 별도 검토 목록에 보존함. 이 기준은 단일 일자·예고 모드에도 적용함. 시행·향후 시행·공포/발령·예고와 회사 관련성 등급은 별개임. --digest-only는 요약 전용, --detailed-guides는 시행 법령군별 병합의 명시 요청에만 사용함. 미래 종료일을 지정해도 실행일 이후 새 발표 자료가 포함된다는 뜻은 아님.

기본 실행 예시:

    .venv/bin/python -m law_change_auto.cli --validate-env
    .venv/bin/python -m law_change_auto.cli --date-from 2026-10-01 --date-to 2026-11-30 --output-dir output/새로운_실행폴더

## 양식

사용자 기준 파일: output/21. 조세특례제한법 시행규칙 시행 안내.docx.
보존 복사: templates/guide_reference.docx.
SHA-256: f182e71716ef43e55b107acce72dcb056583a825d7ec27ed532f7982332f72de.

word/document.xml 이외 패키지를 그대로 보존함. 본문도 문단 역할별 글꼴·크기·강조·정렬·간격과 섹션 순서를 검사함. 개정이유 → 주요내용 → 파급효과 → 신구조문 대비표를 유지하며 예고안의 의견제출기한은 중간에 추가함. 파급효과는 굵게, 표는 9pt·삽입 빨강·삭제 빨강+밑줄을 유지함. Title 스타일, 핵심요약/분류/출처 추가, 대체 글꼴 지정 등은 사용자 요청 없이 적용하지 않음. 렌더링 중 글꼴 대체가 생겨도 DOCX 지정 글꼴을 바꾸어 대응하지 않음.

새 양식을 사용자가 지정하면 원본과 계약 해시·역할 검사·회귀 검사를 함께 갱신함. 파일명만 바꾸거나 해시 검사만 해제하지 않음.

## 요약문 별도 양식 및 내용 계약

요약문 기준은 output/2026-08-01_2026-09-30/법령제개정_주요내용_요약.docx이며, 보존본은 templates/summary_reference.docx임. SHA-256은 2e662890207f0c260cc55f0b8c0e8aa041dbdaf473210d3cd01dccf43d303922임. 개별 안내서 기준 양식과 혼용하지 않음. Letter 페이지, 원본 여백, KoPub 글꼴, 4열 표의 구성·열 너비와 기존 문단 역할을 보존함.

Ⅰ. 개요 → Ⅱ. 당사 관련성 높은 주요 개정 사항 → Ⅲ. 전체 법령 제·개정 요약 → Ⅳ. 미결사항을 유지함. Ⅱ에는 회사 업무 관련 항목의 실제 선별표를 넣음. 시행/예고 등 publication_status가 있어도 안내 문장으로 대체하거나 표를 누락하지 않음. Ⅲ은 전체 목록을 하나의 표로 제시하고 시행·향후 시행·예고는 날짜 칸과 미결사항에서 구분함.

선별은 docs/CANDIDATE_SELECTION.md와 data/selection_rules.json에 따라 개정 원문·회사 역할·실질적 변화로 판단함. 제목만으로 우선 안내하지 않음. Ⅲ 전체 목록은 발행 대상으로 선정된 개정 전체이며, 비선정 후보는 내부 검토 목록에 보존함. 두 표의 번호·법령명·일자·요약문과 개별본 번호는 동일해야 함. 원문 한계·예고·미래 시행 상태를 보존함. 과거 v1 산출물 검증에만 당시 제목 선별 규칙을 적용함.

배포 검증기는 요약 기준 파일 해시, 보존 파트·페이지 설정·문단 역할, Ⅱ 선별 항목, Ⅲ 전체 건수·연속 번호, 두 표의 동일 항목 내용 일치를 검사함. 원문 검토·전 페이지 렌더 시각 검수는 별도로 수행함. 요약문이 기존 양식과 달라지면 그 변경을 사용자가 명시했는지 확인하고, 명시가 없으면 생성기와 검사 기준을 함께 복원함.

## LLM 및 원문

services/enrichment.py에 원문·메타데이터·신구조문·예외·시행일을 전달함. 특정 길이로 잘라 예외를 누락하지 않으며 입력 한도를 넘으면 보류함. 생명보험회사 임직원 맥락, 의무 주체, 공보험/민영보험 및 국가기관/회사 의무의 구별, 예고와 확정 규범의 구별을 명시함.

실 API 응답 ID·모델·토큰·프롬프트·응답·원문 해시가 있는 응답만 성공으로 셈. 캐시는 같은 원문·버전·프롬프트·모델 계약에 맞는 증거를 포함해야 재사용함. 캐시 적중과 새 호출 건수는 따로 기록함. 호출 실패·미사용·증거 없는 수동 문안은 자동 배포 불가임.

법적 의미 검토는 호출 성공과 별도임. 생성된 파급효과의 의무 주체, 회사의 적용 조건, 예외, 시행일, 회사 조치와 원문의 대응을 건별로 검토함. 수정이 필요하면 원문 대조 후 services/enrichment.py의 set_reviewed_impact로 실제 검토자·사유와 API 원문/수정본 해시를 함께 등록하고 published_details.json의 대응 증거를 갱신함. 그 후 문서를 다시 생성하여 새 manifest를 만듦. API 원문을 수정본으로 오인하지 않도록 원 응답은 evidence.raw_response에 보존하고 최종 문구 해시는 별도로 관리함. 호출 실패를 수동 문구로 은폐하지 않음. 원문 충돌·미확보·타법개정은 source_limit으로 표시하고 의미 판단을 보류함.

## 초안에서 배포까지

1. 수집 원문을 collected_details.json에 보존하고, 생성에 사용한 상태를 published_details.json에 저장함.
2. 생성기는 delivery_manifest.json에 개별본 연결·파일 해시·원문/파급효과 해시·실제 API 증거를 기록함. 이 단계는 pending_review임.
3. 아래 명령으로 미완료 검수 기록을 만듦. 기존 기록은 덮어쓰지 않음.

    .venv/bin/python scripts/validate_delivery.py output/새로운_실행폴더 --review-template

4. 전체 후보의 선정·조건부·참고·보류 사유를 실제 검토한 뒤 selection_review에 수행자·사유를 기록함. 실제 원문 대조 후 semantic에 검토자·근거/수정 내용·의무 주체/적용범위/시행일/원문 대응 검토 결과를 기록함. 원문 한계가 있으면 source_limits_acknowledged에 한계 검토 사실을 기록함. 수집 경고가 있으면 collection_review에 범위와 미확인 사항을 검토함. 확인되지 않은 것을 통과시켰다고 기록하지 않음.
5. documents 스킬의 렌더러로 각 DOCX를 PDF·페이지 PNG로 변환하고 전 페이지를 실제 열어 확인함. visual에 DOCX 해시, PDF 경로/해시, 실제 검수 페이지 수, 각 PNG 경로/해시, 검토자를 기록함. 모든 렌더 증거는 실행 폴더 안에 둠. 변환 성공만으로 시각 검수 passed를 기록하지 않음.
6. 검증 후 아래 포장 경로로만 배포함. 필수 검토 누락·파일 변경·원문 변경·대응 누락·참고 양식 불일치·이미지 증거 누락이면 종료 코드 1이며 새 ZIP을 만들지 않음.

    .venv/bin/python scripts/validate_delivery.py output/새로운_실행폴더
    .venv/bin/python scripts/validate_delivery.py output/새로운_실행폴더 --package output/새로운_배포본.zip

배포 ZIP에는 manifest에 명시된 문서·첨부와 검증 기록만 담음. API 키·.env·캐시·임시 스크립트·다른 실행의 파일은 넣지 않음. 파일 생성·API 호출·자동 검사·법적 의미 대조·시각 검수·사용자 수용 여부를 하나의 완료 상태로 합치지 않음.

검토 기록은 수행 사실의 증거이며 진실성을 자동으로 보증하는 장치가 아님. 모델이 의미를 검토한 경우 검토자를 Codex 등 실제 수행자로 적고 사람 검토로 꾸미지 않음. 규칙에 적합한 JSON이라고 법률 판단의 정확성까지 보증하지 않음.

## 회귀 확인

    .venv/bin/python -m pytest -q
    git diff --check

tests/test_delivery_harness.py는 개별본 누락, 문단/패키지 서식 변경, 무증거 문구 주입, 무증거 캐시, 예외·시행일 입력 누락, 미검수 배포를 검증함. 테스트는 외부 네트워크를 사용하지 않으며 모의 API 응답은 실 호출 건수로 보고하지 않음. 이전 잘못된 안내서·원인 기록은 output의 기존 기간 폴더에 보존함.
