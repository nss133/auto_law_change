# 후보 선별 기준 — 2026-11-11

사용자가 승인한 개정 기준임. 법령명·분야 관련성만으로 선정하지 않고, 변경 원문과 회사 역할·실질적 업무 변화를 연결함. 기존의 모든 탐지 후보 개별본 발행 규칙을 아래 계약으로 변경함.

## 적용 범위와 분류

독자는 생명보험회사 전체 업무 담당자임. 보험회사·고용주·개인정보처리자 역할을 포함하되 특정 상품·투자·시설·기금·지원사업의 존재는 추정하지 않음. 등록 법령 168행과 원천 탐지 범위는 유지함.

| 분류 | 기준 | 처리 |
|---|---|---|
| 우선 안내 | 원문에서 회사 역할과 권리·의무·판단기준·기한·비용·절차의 실질적 변화가 함께 확인되는 후보 | 개정 버전별 개별본·목차·요약문 작성. 법률 의미·시각 검수는 별도 |
| 적용 여부 확인 | 특정 사업·투자·시설 등에 따라 영향이 달라지거나 자동 규칙이 적용 주체를 연결하지 못함 | 검토 목록에 보존. 업무 사실과 원문을 확인한 뒤 재분류 |
| 참고 | 원문이 회사 업무 변화 없는 명칭·인용 정비임을 명시하거나 개인 수급·주택세제·신청서류 또는 공공기관 활동에 한정됨을 변경 조문으로 확인 | 원문·사유 보존. 개별본 자동 발행 제외 |
| 원문 확인 보류 | 원문 미확보·충돌·타법개정 등 기존 원문 한계 | 중요도와 별개로 보류. 원문 한계를 해결한 뒤 재평가 |

예고·향후 시행은 시간 상태이며 관련성 등급과 독립임. 원문 한계가 있는 금융 핵심 법령을 저중요도로 간주하지 않음. 명칭 정비라도 보고 수신처·제출 절차·적용대상이 변하면 적용 여부를 확인함.

## 자동 규칙과 검토 경계

실행 기준은 `data/selection_rules.json`, 판정기는 `services/selection.py`임. 제목은 특정 규칙의 적용 범위를 좁히는 데만 사용하며 제목만으로 우선 안내하지 않음. 생성된 요약·파급효과는 선별 근거로 사용하지 않음. 변경 원문의 위치와 정확한 인용문을 기록함.

초기 자동 규칙은 보수적임. 보험회사 업무, 급여·사회보험 신고, 휴가, 임금 제재, 정보처리자 업무에 대해 명시적 변경 표현이 확인된 경우만 우선 안내 후보로 올림. 그 밖의 개정은 조건부 검토로 남으므로 자동 선별 건수를 최종 중요 개정 건수로 설명하지 않음. 단순 키워드 일치나 자동 선별만으로 회사 조치의무를 확정하지 않음.

### 2026-11-11.2 개정

- 신설·확대뿐 아니라 삭제·축소도 확인함. 신구조문의 `<삭 제>` 표시는 HTML 태그가 아니므로 보존함. 빈 신조문을 삭제의 증거로 해석하지 않음.
- 적용 범위를 별도로 확인한 금융기관 정보제공 조항의 삭제는 구조문·신조문을 함께 근거로 기록함. 양육비법 제21조의12 및 시행령 제17조의11의 선지급 신청인 등 정보제공 근거 삭제를 양육비 채무자 관련 제17조의 폐지로 확대하지 않음. 금융기관등에 보험회사가 포함되는 근거와 확인일은 규칙 파일에 보존함.
- 우선 안내는 같은 문장 안의 회사 주체·실질 변경을 확인함. 부정 표현, 다른 기관의 주체, 우선지원 대상기업 등의 한정 조건을 회사의 일반 의무로 처리하지 않음. 별개 문장의 예외로 생명보험회사 변경을 숨기지 않음.
- 개인 주택세제·선지급 신청서류·소방기관 활동의 참고 분류는 법령명만으로 하지 않음. 변경 조문 전체가 확인된 적용 범위에 속하고 회사·고용주·금융기관 관련 변경 근거가 없을 때만 적용함. 새로운 조문이나 회사 역할이 나오면 적용 여부 확인으로 남김.
- 개인 연금·명칭 정비의 설명만 있더라도 신구조문에 회사 업무가 삭제·변경되는 증거가 있으면 참고로 낮추지 않음.
- 난임치료휴가의 고용주 유급기간과 특정 기업에 대한 급여 지원, 공공기관의 데이터 협조 의무와 민간기관의 협조 요청, 국가기관과 출연·보조 사업자의 범위를 구분함.

44건 저장 자료에 대한 대조 결과는 우선 안내 5건, 적용 여부 확인 17건, 참고 5건, 원문 보류 17건임. 같은 저장 원문에 규칙만 적용하면 우선 안내는 3건이며, 공식 신구조문 2건의 삭제 표시 복원으로 2건이 추가됨. 전체 후보는 보존함. 보류 17건의 실질 중요도 및 조건부 17건의 회사 적용 여부는 미확정이므로 이 수치를 선별 정확도나 누락 없음의 증거로 제시하지 않음.

`--selection-review`는 실제 검토자가 후보 ID·원문 해시·분류·역할·변경내용·사유·원문 인용을 기록한 JSON을 받음. 본문·개정 버전이 바뀌거나 인용이 원문에 없으면 거부함. 원문 보류를 검토 문구만으로 우선 안내로 바꿀 수 없음. 검토자의 진실성이나 법적 판단 정확성을 JSON 검사가 보증하지는 않음.

## 기록과 발행

1. `collected_details.json`: 전체 탐지 원문과 날짜 분류·충돌 표시. 원문 텍스트는 보존함.
2. `candidate_details.json`, `candidate_selection.json`, `후보선별_검토목록.md`: 전 후보의 근거·분류·미발행 사유·개별본 연결.
3. `published_details.json`: 우선 안내로 선정된 개정 버전. 개별본 번호와 요약문 전체표·선별표 번호는 이 발행 목록 안에서 동일함. 후보 목록 번호는 별도임.
4. 요약문의 기존 4단 구성과 참고 DOCX는 유지함. Ⅲ의 전체는 발행 대상으로 선정된 전체를 뜻하며 원천 탐지 전체와 구분함. 비선정 후보는 내부 검토 목록에 남음.
5. 우선 안내 0건이면 DOCX 없이 전 후보와 실행 기록을 남김. 이를 변경 없음이나 배포 완료로 표시하지 않음.

배포 manifest v2는 전체 원문·선별 목록·규칙 해시·발행 목록 대응을 검증함. 선정 후보 누락, 비선정 후보 임의 발행, 근거 변조, 규칙 변경 시 차단함. `delivery_review.json`의 `selection_review`에는 전체 후보의 선정·조건부·참고·보류 사유를 실제 검토한 결과를 기록함. 기존 의미·시각 검수와 API 증거 요구는 계속 적용함. 기존 v1 manifest는 당시 제목 선별 기준으로 검증하여 과거 산출물을 변경하지 않음.

수집 단계 신구조문은 API·kordoc의 결정적 추출을 사용함. 수집 중 증거 없는 LLM 대비표 생성을 자동 호출하지 않음. 우선 안내 후보의 요약·파급효과는 enrichment를 통해 생성하며 실 호출 증거가 없는 초안은 배포하지 않음.

## 오프라인 비교와 검토 반영

```sh
.venv/bin/python scripts/compare_selection.py --source output/기존실행/published_details.json --output output/새선별비교
.venv/bin/python -m law_change_auto.cli --date-from 2026-10-01 --date-to 2026-11-30 --selection-review output/새선별비교/검토완료.json --output-dir output/새실행
```

비교 폴더의 `selection_review_template.json`은 검토자·사유 등이 빈 미완료 양식임. 실제 검토한 항목만 `decisions`에 남기고 근거를 기입함. 나머지는 현재 자동 규칙으로 다시 평가함. 복사한 양식을 검토 없이 완료로 처리하지 않음. 규칙 수정 시 기존 사례·부정 사례·CLI 통합시험·배포 차단시험을 실행하고 전후 분류를 비교함.

원문별 사유와 고정 입력 해시를 갖춘 점검 자료는 `scripts/audit_selection.py`로 재실행할 수 있음. `--comparison-dir`의 공식 XML은 새 조문의 법령명·일련번호·공포번호·공포일·시행일이 모두 일치할 때만 새 실행에 반영함. 기존 원본과 과거 실행은 바꾸지 않으며, 이 점검 자료는 사람의 배포 검수 승인 기록을 대신하지 않음.
